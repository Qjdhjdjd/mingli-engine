# 命理规则引擎

把中国传统命理典籍里**可判定的「条件 → 结论」吉凶规则**抽取成结构化数据，用规则引擎执行，每条结论都能回指到具体书名。

> **性质**：文化研究与娱乐用途。命理不具备科学预测效力，不能作为医疗、婚姻、投资、职业等现实决策的依据。

---

## 它做了什么

| 层次 | 内容 |
|---|---|
| 文献层 | 从 **29 部**典籍提取 **152 条**规则（详见 `docs/典籍规则提取表.md`） |
| 规则层 | 通用 DSL：`{"when": {条件树}, "then": {吉凶, 分值, 释义}}`，支持 and/or/not 嵌套、30+ 谓词 |
| 计算层 | 天文黄经推节气 → 四柱排盘 → 十神/藏干/神煞/刑冲合害/纳音/空亡/调候/大运 |
| 解读层 | 大模型把规则输出改写成说明文，逐句标注规则编号，**生成后由程序校验**（详见 `docs/大模型解读说明.md`） |
| 应用层 | 命令行 + 本地 Web（日运日历、四柱八字、六爻纳甲、梅花易数、择日、姓名五格） |

**已实现完整链路**：八字、流日、六爻、梅花、择日、姓名
**仅完成规则形式化**：紫微斗数（8 条规则在库，排盘未实现，原因见文档 3.4）

## 快速开始

无需安装任何第三方库，Python 3.10+ 即可。

```bash
# 1. 命令行
python -m src.cli liuri --date 1990-05-15 --time 10:30 --start 2026-11-10 --days 30
python -m src.cli bazi --date 1990-05-15 --time 10:30 --gender 男
python -m src.cli liuyao --question 求财
python -m src.cli meihua --a 23 --b 17
python -m src.cli zeri --date 2026-11-09
python -m src.cli xingming --surname 4 --given 11 --name 王伟
python -m src.cli narrate --kind liuri --date 1990-05-15 --time 10:30 --day 2026-11-12
python -m src.cli stats

# 2. 本地 Web
python app.py
# 浏览器打开 http://127.0.0.1:8765

# 3. 跑测试
python -m unittest discover -s tests -v
```

## 规则长什么样

```json
{
  "id": "YHP-001",
  "book": "渊海子平",
  "system": "bazi",
  "section": "继善篇",
  "title": "伤官见官",
  "when": {"all": [
    {"ten_god_in_stems": "伤官"},
    {"ten_god_present": "正官"}
  ]},
  "then": {
    "topic": "事业",
    "verdict": "凶",
    "score": -3,
    "text": "伤官见官，为祸百端。古法谓易招是非争讼、仕途阻滞，女命尤忌。"
  },
  "confidence": "A"
}
```

新增一条规则只需往 JSON 里加一个对象，不用改代码。可用谓词见 `engine.py` 的 `PREDICATES`，例如：
`day_master`、`month_branch`、`ten_god_present`、`ten_god_group_count`、`element_extreme`、
`strength`、`shensha`、`relation`、`nayin_relation`、`tiaohou_hit`、`pattern`、`kongwang`、
以及各体系专用的 `zw_*`、`ly_*`、`mh_*`、`zeri_*`、`xm_*`、`lr_*`。

## 流日运势是怎么算的

给定一个人的四柱，把**某一天的干支当成第五柱叠上去**，逐项比对：

| 判定 | 依据 | 例 |
|---|---|---|
| 流日天干对日主取十神 | 《渊海子平》《三命通会》 | 正官值日 +2，七杀值日 −2 |
| 流日支与命局四支论冲合 | 《三命通会》 | 冲日支 −2（冲身宫）、冲月支 −2（冲提纲更重） |
| 伏吟 / 反吟 / 空亡 / 三合 | 《神峰通考》《三命通会》 | 天克地冲为反吟 −3 |
| 建除十二神 + 黄道黑道 | 《协纪辨方书》 | 成、开、定 +1；破、危、闭 −1 |
| 当日是否神煞日 | 《渊海子平》《星平会海》 | 天乙贵人 +2、羊刃 −1、驿马/桃花 0 |

单日分数 = **命中规则得分之和**（不是平均）。用和而不用均值，是因为命中条数本身有信息量：一条 +2 与五条合计 +2 不是一回事，均值会把后者稀释成一样。

大运与流年整段区间不变，标为 `background`，只作背景展示，**不计入逐日分数**——否则等于给每天都加同一个常数，白占权重。

未做的部分：日与日之间的连锁推演（连续叠煞、交节前后的气机转换）。这是有意的简化，非遗漏。

## 大模型解读是怎么接的

定位一句话：**规则引擎负责算出什么，大模型负责讲清楚。** 吉凶、分值、命中的条款，一个都不由模型产生。

```
报告 ──► 事实清单(只含已命中规则+编号) ──► 模型 ──► 校验器 ──► 界面
                                                    │
                              查伪造编号 / 编造分值 / 绝对化措辞 / 无出处判断
```

- **没配模型也能用**：自动走本地模板，同样分四段、同样逐条带编号、同样过校验。
- **配了模型也不会失控**：生成后由程序校验；出现不存在的规则编号或编造分值，直接降级为模板，界面显示原因。
- **两种模式**：`strict` 只解释已命中条目；`exploratory` 允许模型另写一段「【模型推断】」，该段被单独隔离并标注「非典籍结论」。

配置（环境变量优先于文件）：

```bash
export MINGLI_LLM_PROVIDER=deepseek     # deepseek / moonshot / qwen / openai / ollama / custom
export MINGLI_LLM_API_KEY=sk-xxxx
python app.py
```

未配 Key 想验证在线链路，可用自带的假模型：`python tools/mock_llm.py 8799`，再把 `MINGLI_LLM_BASE_URL` 指向它。

校验器查不出什么、隐私影响（出生信息会发给服务商）、单次成本，都写在 `docs/大模型解读说明.md` 里，包括「用真编号说假话」这条盲区。

## 质量措施

- **零死规则**：用 3000 个随机命盘做覆盖审计，每条八字规则至少命中一次（`tests/test_core.py::test_no_dead_rule`）。
- **基准校验**：2000-01-01 戊午日、2024-01-01 甲子日、2024 立春换年等已知案例断言。
- **规则可溯源**：每条命中都带书名、篇目、置信度；界面上逐条展示。
- **不掩盖分歧**：六爻「用克世」一题，《增删卜易》与《卜筮正宗》立场相反，两条规则都在库并各自标注。

## 已知局限

1. 节气用 Meeus 低精度太阳黄经，误差约 ±15 分钟，交节边界出生者月柱可能存疑。
2. 五行力量为简化加权模型（天干 1.0、月干 1.2、藏干 0.6/0.3/0.1），与人工判断会有出入。
3. 分值权重（±1~±4）是本项目为排序而赋，非古籍原有；改动权重会改变综合结论。
4. 神煞取通行口径，羊刃、天乙贵人等存在流派差异。
5. 23:00–23:59 按晚子时（日柱进次日）处理。
6. 紫微斗数未实现排盘。
